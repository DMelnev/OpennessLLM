# Сохранение OpennessLLM на GitHub

## Граница репозитория

Корнем отдельного репозитория должна быть папка `OpennessLLM`, а не родительская
папка конкретного TIA-проекта.

В репозиторий инструмента входят исходный код, скрипты сборки и запуска,
документация, `.artifactignore` и `.gitignore`.

В репозиторий инструмента не должны попадать:

- `CLONE_PROJECT` и любые экспортированные PLC/HMI-блоки;
- файлы проектов TIA Portal `*.apXX`;
- `bin`, `obj`, `out`, `clean-local-last`;
- runtime-карты и runtime-снимки конкретного PLC;
- логи, временные файлы, резервные копии и результаты тестовых прогонов;
- учетные данные, токены, пароли и закрытые сетевые параметры.

Файл `.gitignore` в папке инструмента закрывает локальные build/test-артефакты.
Перед каждым первым push дополнительно проверить список подготовленных файлов:

```powershell
git status --short
git diff --cached --stat
git diff --cached
```

## Видимость и лицензия

До явного решения автора о лицензии рекомендуется создать приватный
репозиторий. Отсутствие файла `LICENSE` не запрещает просмотр опубликованного
кода, но не дает сторонним пользователям ясных прав на его использование,
изменение и распространение.

Публичный репозиторий следует открывать только после отдельной проверки:

- выбран и добавлен подходящий `LICENSE`;
- в истории Git никогда не было TIA-проекта, clone-данных и секретов;
- README не раскрывает нежелательные сведения о производственной сети;
- автор согласен с публичным распространением исходного кода.

Примеры сетевых адресов должны использовать документальные диапазоны, а имена
DB и полей должны быть нейтральными и не раскрывать структуру рабочего проекта.
Перед каждой публичной версией эти условия проверяются повторным поиском по всему
содержимому репозитория.

## Первичная публикация

На машине должен быть установлен Git for Windows либо GitHub Desktop. Для Git
for Windows последовательность такая:

```powershell
Set-Location C:\path\to\OpennessLLM
git init
git add .
git status --short
git commit -m "Release OpennessLLM 0.12.3"
git branch -M main
git remote add origin https://github.com/OWNER/REPOSITORY.git
git push -u origin main
```

`OWNER/REPOSITORY` необходимо заменить фактическими владельцем и именем
репозитория. Репозиторий на GitHub лучше создать пустым, без автоматически
добавленных README, `.gitignore` и лицензии, чтобы первый push не требовал
слияния двух независимых историй.

После публикации версии создать аннотированный тег:

```powershell
git tag -a v0.12.3 -m "OpennessLLM 0.12.3"
git push origin v0.12.3
```

## Проверка после клонирования

На другом компьютере с установленным TIA Portal:

```powershell
.\build.cmd
.\run.cmd version
.\run.cmd self-test
```

Ожидаемая версия: `0.12.3`. Текущий контрольный результат self-test для этой
версии: `28` успешно, `0` ошибок.

Доступ к TIA Portal через Openness дополнительно требует членства пользователя
в локальной группе `Siemens TIA Openness` и повторного входа в Windows после
добавления в группу.
